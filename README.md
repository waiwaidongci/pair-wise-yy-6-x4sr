# 试墨用水准入与签样复核台

由「墨锭试磨室」补建而来，围绕试墨用水准入与签样复核运行。

## 运行

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`（可用 `INK_DB_PATH` 覆盖，`PORT` 覆盖端口）。

## 业务规则

- **一锭一试**：每锭墨只允许有一条未结束（待签样）试墨；重复或并发提交沿用首次结果，不另开新条。
- **水批校验**：水批须登记水源、采集日、余量（ml）和浊度（度）。余量 ≥ 20ml 且浊度 ≤ 二度判为「合格」；余量不足或浊度超过二度仅转「待换水」，不予开试或签样。
- **签样判定**：签样须填试纸、加水量、出墨速度、墨色层次，且复核人与试墨人不得相同；签样提交时再校验一次水批。
- **更正即失效**：水批更正后，凡引用该批水的旧签样立即标记失效，对应墨锭转「待重测」，须重新开试。
- **一致视图**：列表、统计与刷新后内容全部由同一份落盘档案派生。

## 三个业务模块

| 文件 | 模块 | 职责 |
| --- | --- | --- |
| `water-service.js` | 水批校验 | 准入判定（余量/浊度）、水批登记与更正、旧签样失效 |
| `signoff-service.js` | 签样判定 | 一锭一试去重、并发互斥、签样四要素与复核人校验、统计 |
| `archive.js` | 档案落盘 | JSON 档案初始化/迁移、写入锁、编号生成、操作轨迹 |

## 接口

- `GET /api/state` 列表、统计、轨迹（同一份档案派生）
- `GET /api/stats` 统计
- `POST /api/sticks` 墨锭建档
- `POST /api/waters` 水批登记
- `PATCH /api/waters/:id` 水批更正（旧签样立即失效）
- `POST /api/tests/open` 开试（重复/并发沿用首次结果，返回 `reused`）
- `POST /api/tests/sign` 签样复核
